# 架构思路

## 版本

v1版本为概念验证，现已重构为插件化的v2版本。

## docs

我口述的架构决策过程由ai记录整理，放在这里

## apps

这是壳体前后端，负责挂载插件前后端。
使用的dsh的cordis管理插件热插拔。

- server: fastify服务器后端提供路由挂载点，共用值分发，设置管理等。
- web: 单网页应用，提供tab挂载点，动态前端加载等。

热状态新增插件时需要手动刷新，我放弃了watch轮询方案，因为我认为那不是经常事件，资源消耗不值得。

## plugins

这里是tab插件源码，开发时需要编译到tabs触发热重载，其中有两个示例插件:

- anima-example: ComfyUI纯原始的anima工作流，作为基础实现展示
- anima-plus: 我自用的anima工作流，需要的ComfyUI插件见其说明帮助

## packages

共享工具包，目前仅shared，用于保证前后端定义一致性。

## scripts

构建脚本以及其他ai写的脚本。

## dist

构建产物

- app: 前后端壳体
- data: 持久化数据
- tabs: 插件tab所在地，直接将tab插件编译产物放入其中，在设置页点一次「重新扫描插件目录」即装载（D20：宿主不监听目录）

## data、tabs

开发时需要，即dist构建产物的结构，用于实时查看开发效果。
