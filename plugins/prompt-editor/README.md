# prompt-editor —— 提示词编辑器（不负责绘图）

一个**纯编写**的 tab：把提示词按区块组织起来写，输出拼接后的纯文本，自己复制走。
它不连 ComfyUI、不提交作业、不出图 —— 与 `anima-plus` / `anima-example` 没有任何依赖关系。

```
┌────────────────────────────── 工作区 ──────────────────────────────┬────── 输出 ──────┐
│ ┌ 质量 ──────────────────────────┐ ┌ 主体 ────────────────────────┐ │ masterpice, ... │
│ │ [masterpiece] [best quality]   │ │ [1girl] [solo] [silver hair] │ │ 1girl, solo, ...│
│ └────────────────────────────────┘ └──────────────────────────────┘ │ 24 字符 · …     │
│                          [+ 新建区块]                                │ [复制]          │
└──────────────────────────────────────────────────────────────────────┴─────────────────┘
```

## 三个设计约定

1. **顶层结构只属于工作区。** 区块（边框 + 标题 + 颜色）是纯粹的视觉分组，不嵌套；
   最终输出是**拼接后的纯文本**，结构不进输出文本。保存预设时结构随 JSON 一起存 ——
   `doc`（区块/条目）是唯一真源，输出与草稿都是它的派生。
2. **tag 风格 / 自然语言是同一份内容的两种切分视图，开关挂在每个区块上。**
   - tag：按**括号深度 0 的逗号**切块（`(a, b:1.2)` 是一个块），输出时块内用 `, ` 串成一行；
   - 自然语言：按**英文句号**断句，句号留在前一句（只认「句号 + 空白/结尾」，
     所以 `1.5`、`v1.2` 不会被切开；`e.g.` 这类缩写会被当成句尾），输出时块内**每句一行**。
   - **没有全局开关**：每个区块表头各有一个 `tag | 自然语言` 小开关，块与块互不影响
     （质量块用 tag、场景块用自然语言是常态），输出时各块按自己的排版拼，块之间换行。
   - **tag 块末尾自动补英文逗号**：块是拿换行拼的，末尾没逗号的话，后面接的东西会跟最后一个 tag
     粘成一个（以前得自己在最后一个条目上补个逗号）。已经有逗号就不补第二个；自然语言块不补
     （句号就是它自己的结束符）。
   - **工作区的排版跟输出一致**：tag 块横着排成 tag 流，自然语言块**竖排、每句一行**
     （只改排版，不动数据 —— 一条一句仍然是各自独立的条目，译文格也跟着整行铺开）。
   - 换风格 = 把**整块当成一份内容**重切：按旧风格的连接符拼起来，再按新规则切。
     所以 `tag[masterpiece|best quality|8k]` 切到自然语言就是**一条** `masterpiece, best quality, 8k`，
     再切回 tag 又还原成那三条（拼接用的分隔符和切分规则是对偶的，往返可还原）。
     **块与块之间不合并** —— 块是工作区里唯一的结构。
   - 重建内容用的连接符（`CONTENT_SEPARATOR`）和输出的排版分隔符**不是一回事**：自然语言在输出里
     每句一行（`\n`），但拼回一份文本时句子之间必须是空格 —— 原文本本来就是空格分隔的，
     用 `\n` 拼会在切回 tag 时把换行带进 tag 里。
   - 两个例外，都是为了不静默改数据：**禁用的条目不参与合并、原样留在后面**（它本来就不进输出，
     并进去等于悄悄把它放回输出）；**译文清空**（译文对应整条文本，挂在碎片上是错的）；
     整块没内容（空块 / 全禁用）时原样不动。
3. **译文格已经在位、也能编辑持久化，只差数据源。** 每个条目下方那格（虚线小格）单击即可编辑，
   内容存进 `Item.translation`，跟着草稿与预设一起持久化；「译」按钮是下一步自动翻译的入口，
   接上数据源时不用改数据结构。

## 交互（对齐 WeiLin 的 tag 块）

| 操作 | 效果 |
|---|---|
| 单击块 | 就地改名；输入里带逗号（tag 风格）/句号（自然语言风格）会**按该块自己的风格重切**成多个块 |
| 双击块 | 启用 / 禁用（禁用只影响输出，不删内容） |
| 拖动块 | 块内排序；**块类型相同的两块之间也能拖**（tag ↔ tag / 自然语言 ↔ 自然语言）；拖区块表头左侧的 `⠿` 把手排序区块 |
| 区块表头的 `tag \| 自然语言` | 换**这个区块自己**的风格：整块当一份内容重切（别的块不受影响） |
| 「+」输入框 | **失焦即提交**（敲回车也行），不用记着按哪个键；一次粘一串按该块风格切分后逐个加入 |
| 区块色点 | 换颜色（8 色板） |
| 译文格（条目下方那个小格） | 单击就地编辑，失焦保存进 `item.translation`；「译」按钮是下一步自动翻译的入口 |

每个条目都是**上下两个小格**：上格原文（改名 / 禁用 / 拖动 / 删除），下格译文（虚线框，空的时候显示占位）。
译文只是写作时的参照，**永远不进输出**。

**跨块拖条目只认类型相同的块**（`canDropItem` / `moveItem`，见 `client/src/model.ts`）：条目是"按块自己的
规则切出来的碎片"，tag 的一条是逗号段、自然语言的一条是句子；跨类型搬过去，它立刻变成一条没有句号的
"句子"（反过来则会被逗号规则当成一个超长 tag）。两种切分视图之间**没有无损的单条映射**（要映射就得整块
重切，那是 `reflow` 的事），所以类型不同直接不接：光标变"禁止"、目标块不高亮、松手什么都不发生 ——
要换类型请整块换风格。落地时**源块和目标块各发一次条目写**（草稿是按组存的，不发源块它就还是旧顺序）。

### 提交输入必须读 DOM 的实时值（输入法的坑）

`v-model` 在**输入法组字期间不更新**（Vue 的 `vModelText` 里有 `if (e.target.composing) return`），
而中文输入法里"敲回车"往往就是**提交组字**那一下 —— `keydown` 早于 `compositionend`，
此刻 v-model 的 ref 还是空的。所以提交处理器一律读 `inputEl.value`（DOM 实时值）：

```ts
const parts = splitByMode(input?.value ?? adding.value, props.block.mode);
```

只读 ref 的话，中文输入法用户敲回车会被**整段吞掉**：字既没进工作区，输出自然是空的
（线上踩过，`scripts/interaction-test.ts` 里"输入法组字"那组断言专门锁这个）。
加条目 / 改名 / 改译文都是**失焦即提交**（`@blur`，回车也保留），所以"点走就算数"；
提交后还要显式清一次 `input.value` —— ref 没变过时 Vue 不会重渲染，DOM 里的字会留着。

## 数据落在哪

插件自己的空间（D12/D15）：`data/plugins/@comfyui-web+prompt-editor/`

| 文件 | 内容 |
|---|---|
| `presets.json` | 预设库（命名保存的整份结构），原子写 |
| `draft.json` | 当前草稿，**分两段存**：组结构 + 条目 |
| `tags.json` | 词库：**一张表两用** —— 翻译按 `en`/`aliases` 命中，面板按 `categories` 分组。只装"人认可的"（`source:'user'`：手改 / 显式存过的） |
| `settings.json` | 翻译设置：provider、自动译开关、每日上限、超时、两次调用最小间隔 |
| `usage.json` | 当日翻译调用次数（跨天自动清零） |

### 草稿为什么分两段

```json
{ "version": 1,
  "blocks": [ { "id": "b1", "title": "质量", "color": "#6ea8fe", "mode": "tag" } ],
  "items":  { "b1": [ { "id": "x1", "text": "masterpiece", "enabled": true, "translation": "" } ] } }
```

`blocks` 只放**属性**（顺序由数组本身表达），条目按区块 id 分到 `items` 里。于是编辑热路径上
**只有两个写事件**，各自只发"改了多大一块"：

| 事件 | 触发 | 请求 | 请求体大小 |
|---|---|---|---|
| 1. 组属性改变 | 区块增删 / 排序 / 标题 / 颜色 / 风格 | `PUT /draft/structure` | O(区块数)，**一个条目都不带** |
| 2. 某个组编辑完了 | 那个组的条目变了（增删 / 改名 / 禁用 / 排序 / 改译文） | `PUT /draft/blocks/:id/items` | O(该区块条目数) |
| （整份替换） | 载入预设 / 清空工作区 —— 不在热路径上 | `PUT /draft` | 整份 |

整份发的话，改一个字就要把全文档重新序列化 + 传一遍，放大太厉害；而且原来那套"深监听 doc +
防抖 700ms"在窗口里切 tab / 关页面会把最后一次改动丢掉 —— 现在失焦即写，没有待发队列。

两个实现细节：

- **删区块要清孤儿**：写结构时，结构里没有的区块，它的 `items` 一并删掉。
- **乱序兜底**：新建区块时"结构"和"条目"两次请求可能乱序到达，条目先到时给该区块垫一条默认属性
  —— 宁可多一个空区块，也不丢条目；下一次结构写入会按结构把它清掉。

接口（宿主统一加前缀 `/api/p/prompt-editor`）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/presets` | 预设清单（只给摘要：名称 / 时间 / 区块数 / 条目数） |
| GET | `/presets/:id` | 取整份预设 |
| POST | `/presets` | 另存为新预设 `{ name, doc }` |
| PUT | `/presets/:id` | 改名 / 覆盖保存 `{ name?, doc? }` |
| DELETE | `/presets/:id` | 删除 |
| GET | `/draft` | 读当前草稿（两段装配成整份 Doc；盘上还是老格式也认） |
| PUT | `/draft/structure` | 写事件 1：`{ blocks: [{ id, title, color, mode }] }` |
| PUT | `/draft/blocks/:id/items` | 写事件 2：`{ items: [...] }` |
| PUT | `/draft` | 整份替换 `{ doc }` |
| GET | `/settings` | 读翻译设置 + 今日用量 + 词库条数 + provider 清单 |
| PUT | `/settings` | 写翻译设置（越界收敛到范围内） |
| POST | `/translate` | 翻译 `{ texts: [...] }`（1~50 条）→ `{ results: [...], error? }`，**按顺序对齐**。前端逐条发，这个接口本身也支持一批 |
| GET | `/tags` | 词库列表 `?q=&category=&limit=` → `{ tags, total, counts, categories }`（面板用） |
| PUT | `/tags/entry` | 写/改一条 `{ en, zh?, categories?, aliases?, source? }`；不给 `source` 沿用原值 |
| DELETE | `/tags/entry` | 删一条 `{ en }` |

服务端对进来的数据一律过收敛函数（形状 + 长度上限）：请求体和手改坏的 `presets.json` /
`draft.json` 都不该让页面炸掉（读坏了就退化成空文档）。

## 翻译怎么来的

固定 **英 → 中**。一条译文有四种来路，**优先级就是下面这个顺序**：

```
译文格 +「译」（单条 / 整块）+ 自动译
   │  POST /translate { texts: [一条] }        ← 前端逐条发，上一条回来才发下一条
   ▼
插件后端 server.js   ← provider 凭据只在这一侧，永远不下发到浏览器
   ① 词库命中 → 直接回（瞬时、零请求、零配额、没 key 也能用）
   ② 会话缓存命中（这次已经翻过同一个词）→ 直接回
   ③ 没命中 → provider 适配器去翻（串行 + 节流 + 撞限流退避重试）
   ▼
   结果**不写词库**：只挂在那一条条目上（跟着草稿落盘），标成「机」
   人认可它 → 手改译文，或点那个「机」→ 才进 tags.json
```

**为什么 key 放后端**：这个部署是局域网 http（非安全上下文），浏览器直连要过各家 CORS、
key 还得进 localStorage；放后端顺带把缓存 / 限流 / 重试 / 换 provider 都收在一处。
`GET /settings` 只回 provider 清单和开关，凭据类字段一律不回传。

### 词库：一张表两用

```json
{ "version": 2, "entries": {
  "cinematic lighting": { "en": "cinematic lighting", "zh": "电影照明",
    "categories": ["光照"], "aliases": ["cinematic light"], "source": "user", "updatedAt": 0 }
}}
```

- **翻译**按 `en`（大小写/空白归一化）命中，`aliases` 也命中（`cinematic light` → 正名）。
  `aliasIndex` 是每次读盘时重算的派生数据，手改文件时不用管它。
- **面板**按 `categories` 分组 + 搜索（英文/中文/别名都搜）+ 点击插入当前块。
  一个 tag 可以属多个分类（数组，不做单归属）；分类是**写作分类**（画质/光照/人物…），
  不是 Danbooru 官方那 5 类（general 占绝大多数，写提示词时没法找）。
- `source`：`user` 手动入库的（手改译文 / 显式存过）· `import` 导入的 · `builtin` 内置的。
  **面板里不按来源分标签**（进库就是库，一律标「库」），工作区的徽章也不看它（只看"在不在库里"）——
  这个字段现在只剩一个作用：**导入不许覆盖你手动改过的**。
- 没有"按来源清空"这回事：进库的都是手动存过的，不想要就点「删」。
- **老 `dict.json` 自动迁移**：读到 `tags.json` 不存在就把老平表过一遍 `sanitizeTags` 写进新文件，
  老的 `source:'api'`（机器现翻写进去的）归成 `import`；老文件**改名成 `dict.json.migrated`**
  （留个原件，同时免得你删了 `tags.json` 之后它又把那批老条目灌回来）。

两个入口（都在表头）：**词库…** = 管库 + 用库（搜索、改译文/分类/别名、删、插入当前块）；
译文格上的 **「机」** = 把这一条现翻结果存进库。插入会把**译文一起带进块**，所以插完不用再翻。
在面板里**改译文**等于认可它（词条升成 `user`：以后导入不许覆盖它）；只改分类/别名不算。
在工作区点「机」= 把这份现翻的**存进库**，标记跟着从「机」变「库」（进库了就不再是"现翻的"）。

### 词库只装"人认可的"

译文格右下角有个来源标记，一眼能看出这条能不能信：

标记只说一件事：**这条译文在不在词库里** —— 在库里 = 以后零请求，不在 = 每次都得问接口。

| 标记 | 含义 |
|---|---|
| **库** | 在库里：词库命中的、你手改/手填的、点「机」存过的 |
| **机** | 机器现翻的，**还没进库** —— 点一下把这份译文存进词库（标就变「库」），下次别的块遇到同一个词零请求 |

没有标记 = 这条没有译文（或老预设里来路不明的译文）。这是**工作区**里的标记；
词库面板里不分类别，进库就是库，一律标「库」。

为什么不让现翻结果自动进库：词库是"我认可的词表"，混进机器翻的之后就分不出哪些能信了。
代价是同一个词换个块还要再翻一次 —— 所以进程内还有一个**会话缓存**（重挂即清，不落盘），
同一个词在一个会话里只问接口一次。

### 逐条发 + 限流

有道体验版**限流很紧**，实测（`aidemo.youdao.com`，HTTP 一直是 200，限流藏在 body 里）：

| 间隔 | 结果 |
|---|---|
| 连打 | 第 7 次开始 `{"errorCode":411,"msg":"请求频率过快"}` |
| 1.5s | 第 6 次开始 411 |
| **6s** | **连打 8 次全过** |
| 触发后 | 8s 未恢复；几分钟后恢复 |

所以：

- **前端逐条发**：一次只发一条，上一条回来才发下一条。打包成一批只会让一个 HTTP 请求挂很久
  （节流 6s × 10 条 = 1 分钟），而且中途失败会连坐整批。
- **服务端全局节流**（`minIntervalMs`，默认 6000）：记的是"上一次真的打出去"，**跨请求、跨批次都算**
  —— 换个批次、换次点击也照样等。
- **撞上 411 就退避重试**（20s、40s，最多 2 次）：偶尔限流不该让整批红掉。重试用尽才标失败，
  错误码是 `RATE_LIMIT`。

### 四条硬规则（都是"不静默改数据"）

1. **手改的译文写回词库且永不被覆盖**（`source:'user'`）：改过一次，以后自动命中它。
2. **自动译不覆盖任何已有译文**：队列只收"还没有译文"的条目；整块「译」也只翻没有译文的那些
   （要重翻某一条就点它自己的「译」）。
3. **改名清掉旧译文**：译文对应的是**整条**文本，改了文本它就对不上了；而且"有译文就不再自动译"
   会让这个错误一直留着。所以改名时清空译文（自动译随后补上正确的），但**往一条后面追加**
   （第一段文本没变，`a` → `a, b`）时保留 —— 那一段的译文还是对的。
4. **权重语法不许翻坏**：`maskPromptSyntax()` 先把要翻的词剥出来，翻完按原样贴回 ——
   `(masterpiece:1.2)` → `(杰作:1.2)`、`{a|b}` 每支各翻、`<lora:...>` 直接跳过
   （模型名是标识符，翻了就废）。认不出来就整条当普通文本翻。

自动译的隐式调用是被管住的：条目**失焦提交**后攒 400ms 合成一个队列（连着敲几条只排空一次），
然后**逐条**发；配额按**整条文本**算（宁可少翻几条，也不把 `{a|b}` 翻一半）；`maxCallsPerDay` 是护栏，
烧光了自动译停下、格子上留个红框记号，不弹窗、不阻塞写作。失败同理：条目本身照常落盘。

翻译回来的译文也算"这个组编辑完了"，会触发一次该组的条目写入（按组去重，一组一次）——
不然刷新一下刚翻的译文就没了。

## 部署在局域网 http 上（非安全上下文）

浏览器只在**安全上下文**（https / localhost）里提供 `crypto.randomUUID`、`crypto.subtle`、
`navigator.clipboard`；本插件经常就是 `http://10.x.x.x:port` 打开的，所以这两处都做了降级：

| 用途 | 降级 |
|---|---|
| 条目 / 区块 id | `crypto.getRandomValues()`（**不**受安全上下文限制）自己拼 v4 UUID；连它都没有才退回 `Math.random` —— `client/src/model.ts` 的 `newId()` |
| 复制输出 | `navigator.clipboard` 不存在时退化到临时 `<textarea>` + `execCommand('copy')` |

契约测试两条都覆盖：`scripts/contract-test.ts` 会临时摘掉 `globalThis.crypto` 再 SSR 一次首屏
（线上踩过：局域网 http 下首屏直接抛 `crypto.randomUUID is not a function`，整个 tab 白掉）。

> 下一步接翻译时注意同一条：浏览器直连外部 API 时别用 `crypto.subtle` 做签名/加密，那条路在 http 下不存在。

## 词库往后怎么长（**还没做**）

- **导入**：CSV/JSON 两列（英文 + 中文）走 `PUT /tags/entry` 批量灌，`source` 传 `import`
  （`user` 的条目不会被它覆盖）；
  面板里的分类、别名都是现成的，导入后就能按写作分类找词。
- **内置一批常用 tag**：按 `post_count` 从 Danbooru 官方 API 拉 top N（实测 `limit=1000` 可用），
  顺手拉官方 `tag_aliases` / `tag_implications`（零维护），中文自己标或机翻。
- **规模**：几千到几万条 JSON 全量常驻即可（现在就是）；几十万条（Danbooru 全量约 275 万）
  再换 SQLite —— 插件自管存储是允许的（`anima-plus` 就是）。
- 官方只给英文（`name/category/post_count`），**中文必须自己攒** —— 这也是它唯一贵的地方。

价值不在"能查词"，在于**词库命中 = 零请求** —— 体验版约 6 次/窗口的限流下，
这才是让一整块提示词秒出译文的唯一办法。

## 构建

```bash
pnpm --filter @comfyui-web/prompt-editor build          # 或 pnpm build:plugins
pnpm --filter @comfyui-web/prompt-editor build:server   # 只打后端，改 server/ 时更快
pnpm --filter @comfyui-web/prompt-editor typecheck      # vue-tsc，含 server/**
```

服务端源码分成 13 个 `server/*.ts`（每个 ≤300 行），`scripts/build-server.mjs` 用 esbuild 打成**一个** `server.js`
（重挂只给入口加 `?v=`，多文件会命中 Node 的 ESM 缓存，见 `plugins/README.md` §2.4）；`tsconfig.json` 的
`include` 含 `server/**/*.ts`，所以 typecheck 连服务端一起查。产物写进 `tabs/prompt-editor/`，设置页点一次「重新扫描插件目录」即可装载。
